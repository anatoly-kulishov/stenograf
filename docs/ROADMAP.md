# Stenograf MVP

Тонкий клиент (Tauri) и независимое Python-ядро. macOS сначала, Windows после MVP.

Исправления относительно исходного 4-недельного плана зафиксированы в каждом спринте.

## Архитектура

```
React UI
  -> Tauri (Rust): микрофон (cpal) и системный звук (Core Audio tap)
  -> две WAV 16 kHz: mic.wav = «Я», system.wav = собеседники
  -> Python-сайдкар, JSON lines через stdin/stdout
  -> GigaAM v3 + Silero VAD + диаризация (sherpa-onnx)
```

Сайдкар в dev запускается через `uv`. В сборке - PyInstaller `--onedir` (не `--onefile`: onefile распаковывается на каждый старт). Модели не бандлятся: первый запуск качает их в `~/Library/Application Support/stenograf/models`.

## Спринт 1. Захват и сайдкар

1. Монорепо: `app/` (Tauri v2 + React/Vite), `core/` (Python).
2. IPC: JSON lines stdin/stdout. Без FastAPI и без локального порта.
3. macOS: Core Audio process taps (crate `cidre`), не ScreenCaptureKit. Нужен permission на захват аудио, не на запись экрана.
4. Две дорожки вместо AEC. Микрофон - спикер «Я», системный звук - диаризация собеседников. AEC только если на записях без наушников появятся дубли.
5. Ресемпл в 16 kHz (`rubato`) до передачи в модели.
6. Явный индикатор записи в окне и в трее.

Windows (WASAPI loopback, Bluetooth 8 kHz -> 16 kHz) - после MVP.

## Спринт 2. Качество на реальных записях

Сначала набор из 3-5 реальных созвонов и метрики (WER, DER, пропуски реплик). Без этого следующие шаги не калибруются.

1. ASR остаётся GigaAM v3 RNNT punct через sherpa-onnx. Это и есть end-to-end вариант с пунктуацией. Hotwords только с `decoding_method="modified_beam_search"`.
2. Диаризация остаётся в sherpa-onnx (pyannote segmentation 3.0 + NeMo TitaNet). `pyannote/speaker-diarization-community-1` на Hugging Face gated (нужен токен) и тянет torch. Годится только как эталон на машине разработчика, не в дистрибутиве.
3. Выравнивание: VAD-фразы, спикер по пересечению с сегментами диаризации (уже в ядре). Пословные таймкоды - только если фраза цепляет двух спикеров.
4. Словарь терминов (Excel, КТРУ, ОКПД) через hotwords.

## Спринт 3. Локальная аналитика

1. Один бэкенд `llama.cpp` (`llama-server`, Metal на Apple Silicon). Без отдельной ветки MLX. Модель - актуальный Qwen3 8B/14B в GGUF (Qwen2.5 устарел). Перед выбором сверить лицензию commercial use, в том числе открытый GigaChat.
2. Извлечение договорённостей одним запросом с `json_schema` / grammar, не свободным потоком токенов. Поля: ответственный, задача, дедлайн, контекст, цитата, таймкод.
3. Детектор размытости: короткий список маркеров («как обычно», «побыстрее», «в разумные сроки») плюс LLM для формулировки уточняющего вопроса.

## Спринт 4. Хранение, интеграции, релиз

1. SQLite: метаданные встречи, реплики, задачи. Аудио - файлами рядом, не блобами.
2. YouTrack / Jira - после того, как протокол стабилен на реальных записях.
3. UI: список встреч, обязательства с кликом в таймкод, индикатор записи, согласие перед первой записью.
4. GitHub Actions + `tauri-action`: `.dmg`. Подпись Developer ID и нотаризация, включая сайдкар. Без подписи Gatekeeper и TCC ломают захват аудио. `.exe` - когда появится Windows-захват.

## Вне плана, но обязательно

- UX загрузки моделей (прогресс, ошибка сети, повтор).
- Явное согласие на запись. Тихая запись по умолчанию не делается.
